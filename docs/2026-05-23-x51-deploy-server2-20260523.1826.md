## Remaining Risks / Next Steps

1. **Payment module not active yet:** `PAYMENT_DATABASE_URL` is not set in `./litellm/default.env` on server2. To activate the payment endpoints:
   - Add `PAYMENT_DATABASE_URL=postgresql+asyncpg://...` to the env file (pointing to the litellm-postgres instance or a dedicated payment DB)
   - Run `litellm-payment migrate` to create `payment_*` tables via Alembic
   - Recreate the container to pick up the new env var
   - Optionally configure `SEPAY_API_KEY` and/or PayOS credentials for live provider integrations

2. **Payment DB schema:** Alembic migrations have not been applied to the postgres instance. This must be done before the payment module can function.

3. **Standalone vs integrated auth:** The payment router's `get_current_user` dependency currently falls back to `x-user-id` header for standalone use. In production, it should integrate with LiteLLM's `user_api_key_auth` middleware state (already implemented).
